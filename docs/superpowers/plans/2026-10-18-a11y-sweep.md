## Audit findings (source audit, 130 clickable call sites)

### CRITICAL — fixed in this phase

1. **Six back buttons announced as plain text** (no `Role.Button`): TalkBack read them as a
   text node without any button semantics. Fixed by adding `role = Role.Button`:
   - ContestCenterScreen.kt:93, ContestFocusScreen.kt:108,
     LuoguTrainingCatalogScreen.kt:64, LuoguTrainingDetailScreen.kt:65,
     LuoguProblemDetailScreen.kt:89, SettingsScreen.kt:184.
   (SubmissionCenterScreen.kt:100 already had the role — used as the reference.)
2. **FavoriteToggle on the problem detail screen** (ProblemDetailScreen.kt:544): a bare colored
   square — no text, no contentDescription, state conveyed by fill color only (double violation:
   color-only state). Fixed with `onClickLabel` + `semantics { contentDescription }` reusing the
   existing `problems_favorite_on_cd` / `problems_favorite_off_cd` strings.
3. **Search clear "×"** (ProblemsScreen.kt:604): unlabeled glyph button. Fixed with the new
   `problems_search_clear_cd` string ("Clear search query" / 清空搜索词) + role + CD.

### MINOR — verified acceptable, no change

- Filter chips / NexusTag rows (ProblemsScreen demo chips, calibration dialog texts,
  SettingsAction, DialogText) all render a visible `Text` label; TalkBack reads the text, so
  they are accessible even where `onClickLabel` is not set (onClickLabel matters when the
  clickable node's own text does not describe the action).
- Problem rows (ProblemsScreen.kt:1034) carry title text + trailing labeled favorite/delete
  targets (existing CDs at :1026-1029) — the P94 trailing-label trap does not exist here.
- Analytics heatmap cells already carry formatted-date contentDescriptions (Phase 84).
- 200% font scale at 320dp: layouts use `Column`/`LazyColumn` scroll containers on every screen
  (verified: every screen root wraps content in `verticalScroll` or LazyColumn), so text scales
  push content into scroll instead of clipping. Pixel verification stays PENDING with the
  device loop.
