### Task 1: Core startup authority, explicit operation sessions and native lifecycle tests

**Owned files:** Core Storage files, Core Contracts operation-source interface, SchemaMigrator read-only validation refactor, SqliteSyncStore connection acquisition; new Core tests/test-only StorageTestHost project and solution/project references. Do not change CLI/Desktop production code, SyncService or their existing tests in this task. Existing Core factory-using tests can continue on the transitional seam until Task 2. No package changes.

**Read first:** binding spec in full, root AGENTS.md, windows/README.md. Advisory reports copied into this plan workspace are supporting evidence, not requirements and do not override exact spec values.

1. Add stable typed failures/result and exception classifier, workspace path/physical-file policy and shared/exclusive file leases. Use one immediate acquisition attempt per transition. Use exact `ojnexus.lifecycle.lock`; shared OpenOrCreate/ReadWrite/FileShare.ReadWrite, exclusive FileShare.None; no delete sharing or file deletion. Revalidate location under ownership. Path checks include existing ancestors and controlled entries, actual hard-link count for DB/lock and supported local drive. Internal native interop uses SafeFileHandle; no extra dependency.
2. Refactor SchemaMigrator enough to expose internal read-only schema inspection reusing version validators. Keep old Migrate behavior for direct low-level tests; the new startup authority never calls it for an already-current store, and never initializes an existing empty/arbitrary DB. Probe integrity/FKs/header/metadata with explicit ReadOnly/Pooling=false and deferred transaction. Version 0 must validate the recognized version-one base layout and preserve real legacy rows (`SqliteSyncStoreTests.VersionZeroSchemaSql`), not accept metadata-only arbitrary files. Migration uses ReadWrite/Pooling=false under exclusive ownership. Exact schema remains 7.
3. Implement inventory, marker enrollment, staged first creation, exclusive recheck and post-maintenance shared recheck from the spec. Block any incomplete/unknown controlled recovery evidence. For failed first creation retain evidence; no ad-hoc cleanup/recovery protocol. Typed migration/I/O errors; cancellation releases resources safely.
4. Implement IStorageOperationSource and StorageOperationScope with explicit context/permit tracking and Ready -> Draining -> Closed. Implement WindowsStorageSession containing that scope, guarded factory and held shared lease. Public BeginOperation is disposable; RunAsync wrappers always dispose in finally. Idempotent async shutdown first closes admission and cancels outside the gate, then waits operations AND native connection reservations, and releases lifecycle handle last. A context closed while a SQL method is still running must not unlock behind that SQL connection.
5. Add internal guarded factory/store path. Every SQL store entry validates a live owned permit even for early-return branches, reserves before opening, and uses internal connection leases disposed after readers/transactions. Final constructors will be internal after Task 2. For intermediate compilation only, retain and mark the old legacy constructor/open method and unguarded store construction; new session uses exclusively guarded constructors. Never leak raw connections out of the guarded path. Failure to close means retained ownership, not false drain.
6. Add focused Core behavior tests for the spec's states, content preservation, all controlled evidence, real migration, concurrent shared/exclusive leases, invalid old contexts/stores, delayed cleanup/held SQL leases, typed classifications and location policy. Include useful tests proving the baseline corruption pattern at the new API. Baseline real executable RED is already recorded externally; do not claim missing-new-type compile failures as behavioral RED.

Add a test-only `OjNexus.Windows.StorageTestHost` console project (net8.0, Core reference, no package dependency), built by CoreTests project reference with ReferenceOutputAssembly=false, and solution entry. InternalsVisibleTo may target Core.Tests and this host for narrow test access. Actual separate processes must use stdin/stdout readiness barriers and bounded waits. Tests prove two shared holders, exclusive rejection both directions, held lock rename/delete denial, first-run race returning only Ready/Busy without corruption, kill-and-release with stale file retained. Child process roots are unique and kill only owned helpers. No production test verb/env bypass.

### Task 2: Wire real CLI/WPF startup and whole-action drain; remove every bypass

**Owned files:** CLI Bootstrap/Program/ConsoleRenderer and tests; Desktop runtime/ViewModel/MainWindow/XAML/startup controller and tests; SyncService/SyncError and all affected tests; remove Core Task 1 transitional API and migrate existing Core fixtures to guarded sessions. 2. Replace Bootstrap.Create with async startup/session ownership and await disposal. Use Session.RunAsync with explicit operation ISyncStore passed to execution/handle helpers. Project failures through the Core wire codes, JSON `{status:blocked,error:WIRE_CODE}` or short sanitized uppercase human output, reserved exit 6. 3. Refactor SyncService constructor to adapters/clock/generation and RunAsync to accept the operation's explicit ISyncStore. Add additive SyncError.Storage and catch specific provider/storage persistence errors before the generic Network catch. Retain an AppendModule typed failure, attempt final CloseOperation(None) with SyncError.Storage, then throw the retained typed failure even if close succeeds; never return a normal SyncReport that loses CLI exit 6/wire code. Final Open/Close persistence failures reach the typed caller. Update all tests/callers and include storage-failure classification and wire-preservation regressions.
4. DesktopViewModel takes IStorageOperationSource. 5. MainWindow constructor becomes storage-free. Implement testable opening/blocked/ready/closing ownership controller if needed. Loaded async opening constructs VM/runtime only after Ready. No normal action/content access before Ready; serialize retries, handle event failures, cancel and await startup on Closing, dispose any session returned after close began, await whole VM/session drain before allowing final Close. Do not block dispatcher or start disposal only at Closed. All existing screenshot/page navigation paths work when ready.
6. Migrate every old factory fixture to `WindowsStorage.OpenAsync`/session + explicitly held operation context. Dispose contexts before session and before deleting isolated fixture directories; Pooling=false means no global pool clear needed for these paths. Remove ALL transitional public factory constructors, raw OpenConnection, public SQL-store construction, old Bootstrap/DesktopRuntime bypasses.
