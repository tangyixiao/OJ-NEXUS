# Sync POC — Plan

Date: 2026-10-18
Phase: 117 (docs/LONG_RANGE_PLAN.md:320-321)
RFC: docs/rfcs/0001-e2ee-sync.md
Constraint from the plan: **compiled out of release builds unless explicitly enabled.**

## Steps

1. `BuildConfig.SYNC_POC`: `true` in debug, `false` in release (app/build.gradle.kts
   buildTypes). No runtime preference — the phase constraint is about release binaries not
   carrying the surface, so the gate lives in the build graph, not in settings.
2. POC kernel: `core/sync/SyncMergeKernel.kt` — the RFC §3 merge rules as pure functions
   (LWW by (lamport, deviceId) total order; delete strictly-greater rule; conflict list for the
   inspectable conflict log; clock advance). No network, no storage, no crypto — those are
   Phase 118+ decisions if the RFC survives.
3. Tests: `SyncMergeKernelTest` — 6 tests pinning determinism (arrival-order independence,
   device-id tiebreak, stale-delete harmlessness, strictly-greater delete wins, row isolation,
   clock advance).

## Result

- `SyncMergeKernelTest` 6 tests green; full `test assembleDebug` BUILD SUCCESSFUL (762 tests,
  0 failures); `assembleRelease` BUILD SUCCESSFUL with the flag compiled false.
- The release binary carries no entry point: the kernel object is unreferenced by anything
  except its test, and the flag field is `false` in release. A later real implementation must
  guard every entry point with `if (BuildConfig.SYNC_POC)` (documented on the gate object).

## Verdict recorded for Phases 118–120

The POC supports continuing: the merge kernel is ~60 lines of pure Kotlin, far under the
RFC's ~2 k LOC kill line. Crypto + transport remain the real cost drivers and stay unproven —
Phases 118–120 may fill with the storage/transport slices **or** be repurposed for ARC C/D
leftovers if priorities shift. Nothing further is committed by this POC.
