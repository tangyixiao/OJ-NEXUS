# Luogu problem detail cache Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make native Luogu problem details usable offline after first view through a cache-first Room repository with explicit refresh and honest stale-cache fallback.

**Architecture:** Add a judge-scoped Room entity/DAO for detail snapshots. `LuoguProblemDetailRepository` maps between the existing domain model and the cache, returns cache hits without network, and fetches/persists misses or explicit refreshes. The existing ViewModel and safe Markdown screen remain the presentation boundary.

**Tech Stack:** Kotlin, Room, kotlinx.serialization, Coroutines, Retrofit/OkHttp, JUnit, Robolectric Room tests.

**Spec:** `docs/superpowers/specs/2026-08-31-luogu-problem-detail-cache-design.md`

## Global Constraints

- Kotlin + Jetpack Compose + Room; do not add Flutter, React Native, Electron, or WebView.
- All UI strings remain in `res/values/strings.xml` and `values-zh-rCN/strings.xml`.
- No main-site password, cookie, session, CSRF login, cloud account, or cross-device sync.
- Keep Luogu-specific logic behind `judge/luogu`; do not leak DTOs into core domain/UI.
- Preserve all historical README, roadmap, release, and migration data.
- Run `git diff --check`, `test`, `assembleDebug`, and `lintDebug` before release.

### Task 3: Make the repository cache-first with refresh provenance

**Files:**
- Modify: `app/src/main/java/com/ojnexus/judge/luogu/LuoguProblemDetail.kt`
- Modify: `app/src/main/java/com/ojnexus/OjNexusApplication.kt`
- Test: `app/src/test/java/com/ojnexus/judge/luogu/LuoguProblemDetailCacheTest.kt`

**Interfaces:**
- `enum class LuoguProblemDetailSource { CACHE, NETWORK, CACHE_FALLBACK }`
- `data class LuoguProblemDetailResult(val detail: LuoguProblemDetail, val source: LuoguProblemDetailSource)`
- `suspend fun fetch(pid: String): LuoguProblemDetailResult`
- `suspend fun refresh(pid: String): LuoguProblemDetailResult`

- [ ] **Step 1: Write failing repository tests**

Use a real in-memory Room database and a MockWebServer-backed `LuoguClient`:

1. A cached row returns `source == CACHE` and the server receives no request.
2. A missing row fetches JSON, returns `NETWORK`, and creates a readable cache row.
3. `refresh` fetches new JSON and replaces the cached title/content.
4. A timeout/network failure during refresh returns the old detail with `CACHE_FALLBACK`.
5. A malformed/HTTP error during refresh throws `LuoguApiError` and leaves the old row unchanged.

- [ ] **Step 2: Run the tests to verify they fail**

Run:
`.\tools\gradlew-local.bat testDebugUnitTest --tests com.ojnexus.judge.luogu.LuoguProblemDetailCacheTest --no-daemon --console=plain`

Expected: compilation failure because the repository constructor, result type, and DAO wiring do not yet exist.

- [ ] **Step 3: Implement the minimal cache-first repository**

Require a `RemoteProblemDetailDao` in the repository constructor. `fetch` reads the Luogu row
first and never performs network I/O on a cache hit. On a miss it delegates to the existing client,
maps the response, persists it, and returns `NETWORK`. `refresh` always delegates to the client.
Catch only `LuoguApiError.Network` and `LuoguApiError.Timeout` for stale-cache fallback; propagate
all other errors without overwriting the row.

- [ ] **Step 4: Run focused tests and refactor only after green**

Run the focused class again and expect PASS. Then inspect for response-body closure and duplicate
JSON serialization; keep the existing public transport and Markdown parser unchanged.
