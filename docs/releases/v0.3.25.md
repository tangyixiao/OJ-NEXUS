# OJ NEXUS v0.3.25 — Submission center manual recovery / 提交中心手动恢复

## Highlights / 主要变化

- **Queue pending checks / 排队查询待处理结果** — The submission center now exposes `QUEUE
  CHECK` for pending Luogu OpenApp result requests. 提交中心现在为待处理的洛谷 OpenApp 结果请求
  提供“排队查询”。
- **Retry failed checks / 重试失败查询** — Failed local result requests expose `QUEUE RETRY`,
  using an immediate unique WorkManager result job. 本地结果查询失败时提供“重新排队”，使用立即执行
  的本地唯一 WorkManager 结果任务。
- **Foreground remains available / 保留前台查询** — `CHECK RESULT` still performs the existing
  bounded foreground poll, so users can choose immediate foreground or background recovery. “查询结果”
  仍执行现有有界前台轮询，用户可以选择前台立即查询或后台恢复。
- **Bilingual history / 双语历史** — README, roadmap, this Release, and commit explanations use
  English + Chinese. Previous phase notes and Releases remain preserved. README、路线图、本 Release
  和 commit 说明使用中英文结合；之前的阶段说明和 Releases 继续保留。

## Safety boundary / 安全边界

Manual recovery only passes the existing request ID to the official GET result worker. It creates no
submission and never retries a POST. The connected-network constraint and `KEEP` uniqueness remain in
place; scheduler failures stay visible as local action errors. / 手动恢复只向官方 GET 结果 Worker
传递已有 Request ID，不创建提交，也不会重试 POST。联网约束和 `KEEP` 唯一策略保持不变；调度失败会
作为本地操作错误显示。

This release adds no Luogu main-site password login, Cookie, Session, CSRF handling, cloud account,
cross-device sync, local compiler, or custom-input runner. / 本版本不新增洛谷主站密码登录、Cookie、
Session、CSRF 处理、云端账号、跨设备同步、本地编译器或自定义输入运行器。
