# OJ NEXUS v0.3.24 — Luogu OpenApp background result convergence / 洛谷 OpenApp 结果后台收敛

## Highlights / 主要变化

- **Background result jobs / 结果后台任务** — After a Luogu OpenApp submission is persisted
  locally, a unique WorkManager job queries its official asynchronous result. 洛谷 OpenApp 提交
  在本地落盘后，会加入唯一 WorkManager 任务查询官方异步结果。
- **GET-only and bounded / 仅 GET 且有界** — The worker sends no submission POST, uses only the
  request ID, requires network connectivity, and stops after a bounded exponential retry budget.
  Worker 不发送提交 POST，只使用 Request ID，要求联网，并在有界指数退避预算后停止。
- **Restart recovery / 重启恢复** — App startup re-enqueues at most 50 local `PENDING` jobs using
  the same unique namespace; foreground polling remains available. 应用启动时最多恢复 50 个本地
  `PENDING` 任务，并复用同一唯一任务空间；前台轮询仍可用。
- **Bilingual history / 双语历史** — README, roadmap, this Release, and commit explanations use
  English + Chinese. Previous phase notes and Releases remain preserved. README、路线图、本 Release
  和 commit 说明使用中英文结合；之前的阶段说明和 Releases 继续保留。

## Safety boundary / 安全边界

Only the Keystore-backed Luogu OpenApp credential is used by the existing client. Background work
never stores or receives source code, standard input, passwords, main-site cookies, sessions, or
CSRF state. Network/server transient errors stay `PENDING`; permanent errors remain visible in the
local submission center. / 后台任务只通过现有客户端使用 Keystore 保护的洛谷 OpenApp 凭据；绝不保存或接收
源代码、标准输入、密码、主站 Cookie、Session 或 CSRF 状态。网络或服务器瞬时错误保持 `PENDING`，永久错误
在本地提交中心可见。

This release adds no Luogu main-site password login, Cookie/Session/CSRF handling, background
submission, automatic POST retry, local compiler, custom-input runner, cloud account, or
cross-device sync. / 本版本不新增洛谷主站密码登录、Cookie/Session/CSRF 处理、后台提交、自动 POST 重试、
本地编译器、自定义输入运行器、云端账号或跨设备同步。
