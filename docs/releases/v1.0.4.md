## What changed since 1.0.3

The 1.0.3 → 1.0.4 window covers Android phases 121–127: a four-platform capability and
acceptance audit, an Android regression baseline, a shared recovery contract, and the
Phase 127 recovery-safety delivery. Everything below ships in the APK; the network still
only syncs public handles and no credential ever leaves the device.

- **Interrupted restores can no longer corrupt data (Phase 127A).** A snapshot restore that
  is interrupted preserves every source file, the journal records explicit
  save/install/rollback stages, and the app refuses business data access with a
  `LOCAL RECOVERY BLOCKED` screen until the recovered generation is coherent. Applied
  restores reconcile the exact generation before cleanup.
- **Background tasks cannot write into restored data (Phase 127B).** Sync, Luogu result
  polls and scheduled backups run only when their captured data generation matches the
  restored one; refusals are recorded in the sync ledger and periodic queues are re-stamped
  on every start.
- **Import failures are typed and retryable (Phase 127C).** A storage-full import failed
  with an unhandled exception before; import now reports `IMPORT FAILED — FREE STORAGE AND
  RETRY`, `IMPORT FAILED — STORAGE ERROR` or `IMPORT REJECTED` with stable copy, and a
  failed staging attempt cleans up so a retry after freeing space works.
- **Backup export works on Android 8.x–9.x devices (Phase 127D).** Engines before SQLite
  3.27 (no `VACUUM INTO`) export through a checkpointed copy validated like an import
  candidate. Verified end-to-end on a real SQLite 3.19.4 engine (API 27).
- **Snapshot exports are WAL-complete and note state persists (Phase 122).** Snapshot
  archives carry committed WAL rows, and editor/note state survives restarts.
- **Shared recovery contract (Phase 126).** `contracts/recovery/v1` pins 32 synthetic fault
  vectors; the Android decisions above are projections of that corpus, not ad-hoc behavior.
